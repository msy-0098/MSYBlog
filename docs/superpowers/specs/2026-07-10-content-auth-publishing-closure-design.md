# 首页、访客评论与发布流程闭环设计

## 1. 目标

在备案等待期内补齐三个本地可验收的业务闭环：

1. 首页文章、分类和项目全部使用后端真实数据，并具备明确的加载、空数据、错误和重试状态。
2. 访客完成邮箱验证码注册、登录、评论提交和管理员审核，只有审核通过的评论对外展示。
3. 管理员完成文章编辑、Markdown 预览、发布或下线、分类标签维护、封面上传，并能验证文章详情页联动结果。

本轮不处理 DNS、HTTPS、正式域名切换和生产部署。

## 2. 当前状态与主要缺口

### 2.1 首页

首页已经调用文章、分类、项目和站点配置接口，各内容组件也有基础状态文案。当前所有内容请求由同一个 `Promise.all` 管理，任意接口失败都会让文章、分类和项目同时进入错误状态；页面没有重试入口，也缺少局部成功、局部失败的表达。

### 2.2 访客与评论

现有后端已经提供验证码、注册、登录、评论和管理端评论接口，前端文章详情也已有登录注册面板和评论区。主要缺口如下：

- 开发环境未配置 SMTP 时使用固定验证码，验证码随机数实现不适合安全用途。
- 验证码发送没有冷却时间、频率限制和失效记录清理。
- 评论创建后直接进入公开状态，管理端只能事后隐藏，不构成先审后发的审核闭环。
- 前端把发送验证码成功信息和错误信息放在同一个字段中，表单校验、会话失效和待审核反馈不够清晰。
- 评论交互缺少独立组件测试。

### 2.3 管理端发布

现有管理端已具备文章 CRUD、状态字段、分类标签、封面上传和公开详情接口。主要缺口如下：

- 编辑器只有 Markdown 文本框，没有预览模式。
- 正文图片不能直接上传并插入 Markdown。
- 封面上传后没有可视预览和移除操作。
- 保存前校验和接口错误反馈过于笼统。
- 列表不能直接发布或下线，保存后也不能立即验证公开文章详情。
- 缺少覆盖完整发布流程的前端测试。

## 3. 方案选择

采用在现有 Go、Gin、GORM、Vue 3 和 Element Plus 架构上做闭环加固的方案，不新增首页聚合接口，不更换认证机制和编辑器框架。

原因：

- 当前公开接口和管理接口已经基本齐备，复用现有能力可以控制变更范围。
- 三个内容区独立请求即可解决首页局部失败问题，不需要引入新的后端聚合契约。
- 访客 JWT 和管理端 JWT 已形成现有约定，本轮先补服务端安全约束和客户端失效处理。
- Markdown 渲染组件已经存在，可直接复用于管理端预览，避免引入体积较大的编辑器依赖。

## 4. 首页真实内容闭环

### 4.1 数据流

首页挂载后并行启动四个独立任务：站点配置、文章、分类和项目。每个任务维护自己的 `loading`、`error` 和数据状态，失败时只影响对应内容区。

精选文章规则保持不变：

1. 优先查找站点配置中的 `featuredPostSlug`。
2. 如果精选文章不在最新文章结果中，再使用文章列表的 slug 精确筛选能力加载。
3. 精选文章加载失败时保留最新文章内容，并给精选区单独显示错误和重试。
4. 没有配置精选文章时使用最新已发布文章的第一篇。

### 4.2 页面状态

每个内容区支持以下互斥状态：

- `loading`：稳定高度的加载占位，不引起布局跳动。
- `success`：展示后端真实数据。
- `empty`：文章、分类或项目为空时给出对应空状态。
- `error`：展示简短错误信息和“重新加载”操作。

站点配置失败时继续使用现有非敏感兜底资料，但页面明确标记配置暂不可用；文章、分类和项目不使用静态业务数据兜底，避免把假数据误认为真实内容。

### 4.3 验收

- 四个接口全部成功时展示真实内容。
- 任一内容接口失败时，其余内容仍正常显示。
- 空列表显示空状态。
- 单区重试只重新请求该区数据。
- 精选 slug 不在最新六篇时仍可正确加载，且不增加文章阅读量。

## 5. 访客注册、邮箱验证与评论审核闭环

### 5.1 验证码状态模型

验证码继续只保存哈希值，增加以下约束：

- 使用 `crypto/rand` 生成六位数字验证码。
- 有效期保持十分钟。
- 同一邮箱在冷却窗口内不能重复发送。
- 同一邮箱只允许最新一条未使用且未过期验证码参与注册。
- 校验成功后立即标记为已使用。
- 新验证码创建时清理该邮箱已过期或已使用的历史记录。
- 生产模式仍强制要求 SMTP 配置完整。

开发和自动化测试不通过公开 API 暴露固定验证码。测试通过注入验证码生成器或直接准备哈希记录来保持可重复性。

### 5.2 输入与认证约束

- 邮箱使用标准库解析并规范化，拒绝明显非法地址。
- 昵称去除首尾空白并限制长度。
- 密码至少八位，并设置合理最大长度。
- 注册邮箱保持唯一；验证码只对同一邮箱有效。
- 登录失败统一返回“邮箱或密码错误”，避免账号枚举。
- 认证和验证码端点增加进程内限流，按客户端 IP 和邮箱组合限制突发请求。
- 访客令牌失效或接口返回 401 时，前端清理本地访客会话并重新打开登录面板。

### 5.3 评论状态机

评论状态扩展为：

```text
pending -> approved -> hidden
   |           ^          |
   +-----------+----------+
```

- 访客提交评论时创建 `pending` 评论。
- 创建接口返回待审核评论，但公开评论列表只查询 `approved`。
- 管理员可以把 `pending` 或 `hidden` 改为 `approved`。
- 管理员可以把 `pending` 或 `approved` 改为 `hidden`。
- 管理员可以删除任意评论。
- 管理端列表支持按状态识别待审核、已通过和已隐藏评论，并优先呈现待审核内容。

### 5.4 前端交互

- 登录与注册使用明确的字段级校验，不发送明显无效请求。
- 发送验证码按钮显示冷却倒计时，期间不可重复点击。
- 成功、提示和错误使用独立状态，不再共用错误字段。
- 注册成功后自动建立访客会话。
- 评论提交成功后清空输入框，并提示“已提交，审核通过后会公开显示”。
- 公开评论列表不会立即出现待审核评论。

### 5.5 验收

- 验证码只能用于目标邮箱且只能使用一次。
- 冷却期内重复发送被拒绝。
- 正确验证码可以注册并自动登录，错误或过期验证码不能注册。
- 未登录访客不能评论。
- 新评论默认待审核，公开列表不可见。
- 管理员通过后公开可见，隐藏后再次不可见。

## 6. 管理端发布流程闭环

### 6.1 编辑器

编辑器采用“编辑 / 预览”分段控制：

- 编辑模式保留 Markdown 文本输入。
- 预览模式复用公开端 `MarkdownRenderer`，确保后台预览与文章详情渲染一致。
- 正文图片上传成功后，在当前光标位置插入 Markdown 图片语法；无法获取光标时追加到正文末尾。
- 封面上传后立即展示缩略预览，并可清除封面。
- 分类为必选项，标签为多选项。
- 标题、slug、正文、分类和状态在提交前进行明确校验。

### 6.2 状态与列表操作

文章继续使用现有 `draft`、`published` 和 `hidden` 状态：

- 草稿：只在管理端可见。
- 已发布：公开列表、首页和详情页可见。
- 已隐藏：从公开接口移除，但管理端保留。

管理端文章列表增加发布和下线快捷操作，内部仍调用现有更新接口并提交完整文章数据，避免新增只更新状态的特殊契约。

### 6.3 保存后的联动

- 保存草稿后返回文章列表，并显示保存结果。
- 发布成功后提供“查看文章”入口，跳转到 `/posts/:slug` 验证公开详情。
- 下线成功后公开详情应返回不存在，首页和列表不再出现该文章。
- 编辑页加载、上传、保存分别维护错误状态，失败后保留用户尚未保存的正文。

### 6.4 验收

- Markdown 预览与公开详情主要内容一致。
- 封面和正文图片上传后能够正常引用。
- 分类与标签保存后在文章详情正确显示。
- 草稿发布后出现在公开详情和首页数据中。
- 已发布文章下线后从公开接口移除。
- 保存失败时输入内容不丢失。

## 7. 测试策略

所有行为变更采用测试先行。

### 7.1 后端

- 验证码安全生成、冷却、过期、单次使用和邮箱绑定测试。
- 注册、登录和鉴权失败测试。
- 评论从待审核到通过、隐藏和删除的路由测试。
- 公开评论只返回 `approved` 的测试。
- 文章发布、隐藏、分类标签和上传联动测试。

### 7.2 前端

- 首页四类数据的成功、局部失败、空状态和单区重试测试。
- 登录注册字段校验、验证码冷却和会话失效测试。
- 评论提交待审核提示和公开列表刷新测试。
- 管理端评论审核操作测试。
- Markdown 预览、正文图片插入、封面预览和发布联动测试。

### 7.3 完整验证

- 后端执行 `go test ./...`。
- 前端使用 pnpm 安装依赖后执行测试和生产构建。
- 使用浏览器分别检查桌面和移动视口的首页、评论区、管理端编辑器和文章详情。
- 提交前分别检查两个仓库的 `git status --short`，确认没有依赖、构建、上传、数据库、日志或敏感配置进入版本库。

## 8. 提交与发布边界

- `backend/` 和 `frontend/` 分别提交。
- 每个有提交的仓库分别推送到 GitHub `origin` 和 Gitee `gitee`。
- 不提交根目录本地文档、凭据、环境变量、数据库、上传文件、依赖和构建产物。
- 本轮不连接生产服务器，也不修改 DNS、HTTPS 或正式域名配置。

## 9. 非目标

以下内容不在本轮范围：

- 找回密码和修改密码。
- HttpOnly Cookie 认证迁移。
- 第三方登录。
- 评论回复、点赞、邮件通知和敏感词审核。
- 首页聚合接口。
- 更换 Markdown 编辑器框架。
- DNS、HTTPS、正式域名上线和生产部署。
